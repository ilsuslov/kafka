# kafka



Что сделано
1. Поднял кластер из 2 брокеров и ZooKeeper через docker-compose. Два брокера нужны, чтобы работала репликация фактора 2.
2. Создал топик `my-topic` (3 партиции, 2 реплики) через консольную утилиту.
3. Написал приложение на Python с библиотекой `confluent-kafka`. Внутри работают:
   - Продюсер: отправляет сообщения асинхронно.
   - SingleMessageConsumer: читает по 1 сообщению, смещения коммитятся автоматически.
   - BatchMessageConsumer: набирает ~10 сообщений, обрабатывает их и коммитит смещение вручную один раз.
4. Запустил приложение в двух экземплярах через `replicas: 2` в docker-compose.
5. Настроил гарантию доставки At Least Once.

## Как запустить
1. Установить Docker и Docker Compose.
2. В папке с файлами выполнить:
   
   docker compose up -d
 3. Подождать, пока поднимутся брокеры.
 4. Создать топик:   docker compose exec kafka1 kafka-topics.sh --create --topic my-topic --partitions 3 --replication-factor 2 --bootstrap-server kafka1:9092
 5. docker compose logs -f app  ## смотреть логи


Проверка:
В логах видно, что [SINGLE] и [BATCH] выводят одинаковые Сообщение X. Это значит, что разные group.id заставили Kafka отдавать данные обоим независимо.
[BATCH] пишет "Закоммичено смещений для N сообщений" раз в ~10 записей, а [SINGLE] работает без пауз.
docker compose ps показывает два контейнера app. Оба шлют данные и читают их, конфликтов нет.
Если остановить один брокер (docker stop kafka2), продюсер временно покажет ошибки доставки, но после retries работа восстановится. Сообщения не пропадут.


Пояснения:
acks: 'all' Producer Продюсер ждёт ответа от всех синхронизированных реплик. Без этого гарантия At Least Once не работает.
retries: 3  Producer При временных ошибках сети или смене лидера продюсер попробует отправить ещё 3 раза.
enable.auto.commit: True SingleConsumer Kafka сама сохраняет смещения в фоне каждые 1000 мс.
enable.auto.commit: False BatchConsumer Отключает автокоммит. Смещение сохраняется явно через commit(asynchronous=False) только после обработки пачки.
fetch.min.bytes / fetch.max.wait.ms BatchConsumer Брокер копит данные, пока не наберётся 1024 байт, но ждёт не дольше 500 мс.
group.id Оба консьюмера Уникальные ID групп. Kafka использует их для отслеживания прочитанных смещений. Разные группы = независимое чтение.

Реализовано: асинхронная отправка, два режима потребления, ручное и автоматическое управление смещениями. 
Настройка acks=all и retries обеспечила доставку At Least Once. 
Параметры fetch.min.bytes и fetch.max.wait.ms показали, как можно оптимизировать чтение пачками. 
Разделение консьюмеров по group.id позволило параллельно обрабатывать один топик без конфликтов.
